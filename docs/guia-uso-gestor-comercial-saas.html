Guía de uso
Gestor Comercial SaaS

Manual operativo para comercios: dashboard, productos, clientes, cuenta corriente, proveedores, ventas, compras, facturación electrónica, usuarios, notificaciones y mi cuenta.

Alcance: guía basada en la estructura actual del proyecto Laravel/Inertia y en la documentación fiscal interna disponible.

Importante: algunas opciones pueden mostrarse u ocultarse según el comercio activo, el rol del usuario, las funcionalidades contratadas y la configuración del módulo.

1. Acceso, roles y contexto del comercio

La aplicación trabaja con un contexto de comercio activo. Cada usuario accede a la información del comercio al que pertenece y las consultas se filtran por ese comercio para evitar mezclar datos entre negocios.

Roles principales

Rol Qué puede hacer Uso recomendado
Administrador del comercio Opera todos los módulos del comercio y administra usuarios, notificaciones y configuración fiscal disponible. Dueño, encargado o responsable administrativo.
Staff Opera módulos del comercio según las pantallas habilitadas. No administra usuarios ni ajustes sensibles. Cajero, vendedor o personal operativo.
Superadmin Administra comercios, funcionalidades, planes, configuración fiscal general y opciones globales del SaaS. Equipo interno del sistema.
Acceso bloqueado: si el comercio está inactivo, el usuario no pertenece al comercio o hay restricciones de facturación del SaaS, el sistema puede impedir el acceso al panel operativo.

2. Flujo diario recomendado

  1. Ingresar al Dashboard y revisar ventas del día, alertas de stock bajo, vencimientos y últimas operaciones.
  2. Verificar Productos con poco stock, sin precio, sin costo o con lotes próximos a vencer.
  3. Registrar Compras antes de vender mercadería recién ingresada para mantener stock y costo actualizados.
  4. Usar Ventas para registrar operaciones del mostrador, cobros parciales y ventas a cuenta corriente.
  5. Controlar Cuenta corriente para cobrar saldos pendientes y enviar recordatorios.
  6. Si está habilitada, revisar Facturación electrónica para confirmar comprobantes autorizados, rechazados o pendientes de conciliación.
  7. Al cierre, revisar ventas recientes, medios de pago y transferencias por destino o sector si el comercio usa configuración avanzada.

3. Dashboard

El dashboard resume la actividad comercial y permite detectar problemas operativos sin entrar módulo por módulo.

Indicadores visibles

  • Ventas de hoy: total vendido en el día actual.
  • Ventas del mes: acumulado del mes en curso.
  • Productos activos: cantidad de productos disponibles para operar.
  • Proveedores: cantidad de proveedores cargados.
  • Stock bajo: productos cuyo stock está por debajo del mínimo definido.
  • Top productos: productos más vendidos en el período calculado.
  • Últimas ventas y compras: actividad reciente para control rápido.
  • Alertas de vencimiento: productos o lotes próximos a vencer cuando el producto usa vida útil o lotes.

Acciones rápidas

  • Nueva venta: abre el flujo de venta/POS.
  • Nueva compra: permite ingresar mercadería y actualizar stock.
  • Revisar stock bajo: lleva a productos filtrados por necesidad de reposición.
Buenas prácticas: usar el dashboard al inicio y al cierre del día. Si aparecen muchos productos sin precio, sin costo o con stock negativo, conviene corregir esos datos antes de seguir operando.

4. Categorías

Las categorías ordenan los productos y facilitan búsquedas, filtros y reportes.

Listado

  • Permite buscar por nombre o descripción.
  • Muestra categorías del comercio activo.
  • Puede filtrar o indicar categorías activas/inactivas según la pantalla.

Crear o editar categoría

Campo Uso
Nombre Nombre visible para clasificar productos.
Slug Identificador amigable. Puede generarse desde el nombre si la pantalla lo permite.
Descripción Detalle interno opcional.
Activa Define si la categoría queda disponible para uso operativo.
Impacto: desactivar una categoría no debería borrar productos. Sirve para dejar de usarla sin perder historial.

5. Productos, stock y lotes

Productos es uno de los módulos centrales. De su calidad de carga dependen las ventas, compras, reportes, alertas y cuenta corriente.

Filtros del listado

  • Búsqueda: por nombre, código, SKU, código de barras u otros campos disponibles.
  • Categoría: restringe el listado a una categoría.
  • Sin precio: detecta productos que no deberían venderse aún.
  • Sin costo: útil para mejorar márgenes y reportes.
  • Sin stock / con stock / stock bajo: ayuda a reposición.
  • Vencimientos: permite revisar productos o lotes próximos a vencer.

Datos principales del producto

Grupo Campos habituales Recomendación
Identificación Nombre, descripción, código de barras, SKU, slug. Usar códigos consistentes para acelerar ventas por escáner o búsqueda.
Clasificación Categoría y proveedor. Asignar categoría desde el inicio para ordenar reportes y filtros.
Unidad de venta Unidad, kilo o gramo. Configurar correctamente productos fraccionables para evitar errores de precio.
Precio y costo Precio de venta y costo. Completar ambos para vender y calcular margen.
Stock Stock actual y stock mínimo. Definir mínimo realista para que las alertas sean útiles.
Vencimiento Vida útil, alertas y lotes. Usar lotes en alimentos, medicamentos u otros productos con vencimiento.

Lotes y vencimientos

Cuando un producto maneja lotes, el sistema puede registrar código de lote, cantidad y fecha de vencimiento. En ventas, la lógica puede consumir primero los lotes más próximos a vencer para reducir pérdidas.

  • Al cargar compras, registrar lote y vencimiento si el producto lo requiere.
  • Revisar alertas del dashboard y filtros de productos para actuar antes del vencimiento.
  • Usar correcciones de lote cuando el stock físico no coincide con el sistema.
Control operativo: un producto sin precio no debería venderse. Un producto sin costo puede venderse, pero afecta reportes de rentabilidad.

6. Clientes

Clientes permite centralizar datos de contacto, historial de ventas y deuda. Es clave para ventas pendientes, cobros parciales y cuenta corriente.

Listado y búsqueda

  • Buscar clientes por nombre, documento, teléfono, email u otros datos disponibles.
  • Identificar clientes con saldo pendiente o deuda alta.
  • Entrar al detalle para ver ventas recientes, movimientos y recordatorios.

Crear o editar cliente

Campo Uso recomendado
Nombre Dato mínimo para identificar al cliente.
Documento Útil para comprobantes, control interno y búsqueda.
Teléfono / WhatsApp Necesario para recordatorios de deuda por WhatsApp.
Email Necesario para recordatorios por correo.
Dirección / notas Información administrativa opcional.
Preferencias de recordatorio Permiten definir canal preferido o desactivar avisos para ese cliente.

7. Cuenta corriente

Cuenta corriente muestra saldos pendientes y movimientos generados por ventas no cobradas totalmente.

Cómo se genera deuda

  • Una venta pendiente genera deuda por el total.
  • Una venta parcial genera deuda por el saldo restante.
  • Para ventas pendientes o parciales, el sistema exige cliente asociado.

Registrar pagos

Al registrar un pago, el sistema aplica el importe a las ventas pendientes del cliente, priorizando las más antiguas. Esto mantiene el historial ordenado y evita elegir manualmente cada deuda cuando no hace falta.

Recordatorios

  • Se pueden preparar avisos por WhatsApp o email según datos del cliente.
  • Conviene revisar el mensaje antes de enviarlo, especialmente si hay acuerdos particulares.
  • Si un cliente pidió no recibir avisos, respetar la configuración de recordatorios.
Impacto: cuenta corriente no es solo un listado de deudas. Afecta cobranza, historial del cliente y control del flujo de caja.

8. Proveedores

Proveedores permite mantener ordenada la información de quienes abastecen al comercio y vincular compras a cada proveedor.

Datos habituales

  • Nombre o razón social.
  • Contacto responsable.
  • Teléfono y email.
  • Dirección.
  • Notas internas.

Uso en compras

Al registrar una compra, asociar el proveedor mejora el historial, facilita reclamos y permite analizar de dónde proviene la mercadería.

9. Ventas y POS

El módulo de ventas está pensado para operaciones de mostrador: búsqueda rápida de productos, carga de ítems, medios de pago, cuenta corriente y, si está habilitada, emisión fiscal.

Crear una venta

  1. Ingresar a Ventas y seleccionar Nueva venta.
  2. Buscar productos por texto, SKU o código de barras. También se pueden cargar ítems manuales si el flujo lo permite.
  3. Agregar cantidades. En productos por peso, controlar la unidad usada.
  4. Seleccionar cliente si la venta será parcial, pendiente o necesita quedar asociada.
  5. Elegir estado de pago: pagada, parcial o pendiente.
  6. Elegir medio de pago: efectivo o transferencia. Si es efectivo, registrar importe recibido para calcular vuelto.
  7. Si el comercio usa configuración avanzada, seleccionar sector y destino de transferencia cuando corresponda.
  8. Confirmar la venta.

Qué ocurre al confirmar

  • Se guarda la venta con sus ítems.
  • Se descuenta stock de los productos vendidos.
  • Si hay lotes, se consumen según la lógica configurada para vencimientos.
  • Si la venta queda parcial o pendiente, se registra saldo en cuenta corriente.
  • Si facturación electrónica está habilitada y configurada para emisión automática, se intenta emitir el comprobante fiscal.

Detalle de venta

Desde el detalle se puede revisar cliente, ítems, pagos, estado de deuda, comprobantes, impresión o descarga de documentos disponibles.

Antes de vender: si el producto no tiene stock suficiente o no tiene precio, corregirlo antes de confirmar. Forzar operaciones sin datos correctos afecta stock, caja y reportes.

10. Compras

Compras registra ingreso de mercadería, actualiza stock, costo y lotes. Es recomendable cargar compras antes de vender productos recién recibidos.

Crear una compra

  1. Ingresar a Compras y seleccionar Nueva compra.
  2. Elegir proveedor si corresponde.
  3. Definir fecha y notas internas.
  4. Agregar productos existentes o crear nuevos productos desde la compra si el flujo lo permite.
  5. Completar cantidad y costo unitario.
  6. Registrar lote y vencimiento si aplica.
  7. Confirmar la compra.

Impacto de la compra

  • Aumenta el stock disponible.
  • Actualiza costos del producto según la lógica vigente.
  • Registra lotes recibidos cuando se informan.
  • Deja historial para consultar compras por proveedor y fecha.

11. Facturación electrónica y ARCA

El módulo de facturación electrónica se muestra cuando la funcionalidad está habilitada para el comercio y la configuración fiscal general está activa. La aplicación delega la emisión fiscal en una API fiscal externa y conserva el estado local de los comprobantes.

Diseño actual: el SaaS no guarda certificados, claves privadas ni tokens WSAA. La generación de clave, administración de certificados, autenticación contra ARCA y emisión se delegan en la API fiscal externa configurada.

Precondiciones para usar facturación electrónica

  • La variable/configuración fiscal general debe estar habilitada.
  • El comercio debe tener habilitada la funcionalidad de facturación electrónica.
  • Debe existir configuración fiscal del comercio: CUIT, ID externo fiscal, punto de venta, tipo de comprobante, concepto, modo de autorización y actividades.
  • La API fiscal externa debe estar accesible y con token válido.
  • El comercio debe tener certificado fiscal activo en el ambiente correspondiente.

Qué se ve en el módulo

  • Estado de configuración del comercio.
  • Conexión con la API fiscal.
  • Resumen de comprobantes autorizados, rechazados, con error, inciertos o en proceso.
  • Actividad fiscal reciente.
  • Puntos de venta y datos de configuración cuando están disponibles.
  • Gestión de credenciales para administradores del comercio.

Flujo de credenciales con ARCA

  1. El administrador verifica que el CUIT y el ambiente fiscal del comercio sean correctos.
  2. Desde la app solicita la generación de CSR. La app llama a la API fiscal externa.
  3. La API fiscal genera o reutiliza la clave privada y devuelve el CSR. La clave privada queda fuera del SaaS.
  4. El administrador usa ese CSR en ARCA para obtener el certificado del ambiente correspondiente.
  5. ARCA entrega un certificado .crt.
  6. El administrador carga el certificado en la app.
  7. La app envía el certificado a la API fiscal, que valida que coincida con la clave privada y activa las credenciales.
  8. Con certificado activo, la API fiscal puede autenticar contra WSAA y emitir comprobantes mediante el servicio fiscal correspondiente.

Testing/homologación vs producción

Aspecto Testing / homologación Producción
Objetivo Probar integración, emisión, errores y PDF sin impacto fiscal real. Emitir comprobantes válidos para la operación real del comercio.
Certificado Debe obtenerse para el ambiente de prueba. No sirve para producción. Debe obtenerse para el ambiente productivo. No usar certificados de testing.
Endpoints WSAA ARCA documenta endpoint de homologación para autenticación. ARCA documenta endpoint productivo separado.
Datos del comercio Usar configuración fiscal de prueba y punto de venta habilitado para testing. Usar CUIT, punto de venta, actividades y condiciones fiscales reales.
Validación Permite probar rechazos, reintentos y conciliación. Requiere revisión previa con contador o responsable fiscal.
No mezclar ambientes: testing y producción tienen credenciales, certificados y endpoints distintos. Un certificado de homologación no debe usarse en producción, y una configuración productiva no debe probarse como si fuera testing.

Configuración fiscal del comercio

  • CUIT: identificación fiscal del comercio.
  • ID externo fiscal: identificador usado por la API fiscal externa.
  • Ambiente: testing u producción.
  • Punto de venta: punto habilitado para emitir comprobantes.
  • Tipo de documento y comprobante: por ejemplo factura C si corresponde al régimen del comercio.
  • Concepto: productos, servicios o mixto.
  • Modo de autorización: CAE normal, CAEA contingencia o automático.
  • Actividades: actividades fiscales asociadas al comercio.

Emisión desde ventas

  1. El usuario confirma la venta.
  2. El sistema guarda la venta localmente.
  3. Si corresponde, construye el payload fiscal con datos de venta, cliente, comprobante e ítems.
  4. La app llama a la API fiscal externa con clave de idempotencia para evitar duplicar comprobantes.
  5. La API fiscal solicita autorización a ARCA.
  6. El sistema guarda el estado fiscal devuelto: autorizado, rechazado, error, incierto o en proceso.
  7. Si el comprobante queda autorizado, se habilita la descarga del PDF fiscal con QR.

Estados fiscales

Estado Significado Acción recomendada
authorized Comprobante autorizado por ARCA. Tiene CAE o CAEA y numeración fiscal. Descargar PDF, entregar al cliente y conservar registro.
rejected ARCA rechazó la solicitud por validación fiscal o datos incorrectos. Corregir configuración/datos y reintentar si corresponde.
error Error controlado de integración o validación local/API. Revisar mensaje, configuración y conectividad.
uncertain No se sabe si ARCA autorizó o no, por timeout o respuesta inconclusa. Conciliar antes de reintentar para evitar duplicados.
processing La emisión quedó en proceso. Esperar o ejecutar conciliación según la pantalla disponible.

CAE, CAEA y PDF fiscal

  • CAE: autorización electrónica habitual para comprobantes.
  • CAEA: autorización usada para escenarios de contingencia si el comercio está configurado para eso.
  • PDF fiscal: se descarga solo cuando el comprobante está autorizado y tiene los datos mínimos necesarios.
  • QR: el PDF incluye QR fiscal con datos del comprobante para validación.

Gestión operativa con ARCA

  1. Confirmar con contador el tipo de comprobante, punto de venta, condición fiscal y actividades.
  2. Crear o habilitar el punto de venta fiscal correspondiente.
  3. Generar CSR desde la app para el ambiente correcto.
  4. Obtener certificado en ARCA usando ese CSR.
  5. Cargar el certificado en la app y verificar que quede activo en la API fiscal.
  6. En testing, emitir ventas de prueba y revisar rechazos, PDF y conciliación.
  7. En producción, hacer una primera emisión controlada y validar número, CAE/CAEA, vencimiento, QR y datos fiscales.

12. Usuarios

La administración de usuarios está disponible para administradores del comercio.

Crear usuario

  • Completar nombre y email.
  • Asignar rol: administrador o staff.
  • Definir si queda activo.
  • El sistema puede enviar acceso por email según configuración disponible.

Buenas prácticas

  • Dar rol administrador solo a personas que deban cambiar configuración sensible.
  • Desactivar usuarios que ya no trabajan en el comercio.
  • No compartir usuarios entre varias personas: cada operador debería tener su cuenta.
  • El sistema protege acciones críticas como desactivar el propio usuario o dejar el comercio sin administradores activos.

13. Notificaciones

Notificaciones permite definir avisos automáticos del comercio. Está disponible para administradores.

Configuración disponible

  • Activar o desactivar notificaciones del comercio.
  • Enviar al email del comercio.
  • Enviar a usuarios administradores.
  • Agregar destinatarios extra.
  • Activar alertas de stock bajo.
  • Activar alertas de vencimiento.
  • Activar recordatorios de mantenimiento si el módulo lo usa.
  • Definir horas mínimas entre avisos.
  • Definir ventana horaria de envío.

Vista previa e historial

La pantalla muestra destinatarios previstos, alertas detectadas y envíos recientes para validar que la configuración funcione como se espera.

Impacto: una buena configuración evita que el comercio se quede sin productos críticos o pierda mercadería por vencimientos.

14. Mi cuenta

Mi cuenta permite administrar datos personales del usuario autenticado.

Opciones habituales

  • Actualizar nombre y email.
  • Cambiar contraseña.
  • Eliminar cuenta si el flujo está habilitado.
Antes de eliminar cuenta: validar si el usuario es administrador único del comercio o si hay tareas pendientes. La eliminación puede afectar el acceso futuro.

15. Checklists operativos

Alta inicial del comercio

  • Confirmar datos del comercio y usuarios administradores.
  • Cargar categorías principales.
  • Cargar proveedores frecuentes.
  • Cargar productos con precio, costo, stock mínimo y código de barras/SKU si aplica.
  • Configurar lotes y vencimientos para productos sensibles.
  • Cargar clientes con datos de contacto si se usará cuenta corriente.
  • Configurar notificaciones.
  • Si corresponde, configurar facturación electrónica y probar en testing antes de producción.

Inicio del día

  • Revisar dashboard.
  • Controlar stock bajo y vencimientos.
  • Registrar compras pendientes del día anterior.
  • Verificar comprobantes fiscales pendientes o inciertos.

Venta correcta

  • Buscar producto por código o nombre.
  • Confirmar precio y cantidad.
  • Seleccionar cliente si hay deuda, factura nominada o venta pendiente/parcial.
  • Elegir medio de pago correcto.
  • Confirmar vuelto si es efectivo.
  • Emitir o revisar comprobante fiscal si aplica.

Compra correcta

  • Seleccionar proveedor.
  • Cargar productos y cantidades reales.
  • Registrar costo unitario.
  • Informar lote y vencimiento si corresponde.
  • Confirmar que el stock haya aumentado.

Pase a producción de facturación electrónica

  • Validar datos fiscales con contador.
  • Confirmar que el comercio tenga habilitada la funcionalidad.
  • Configurar ambiente production en la API fiscal y en el comercio.
  • Generar CSR para producción.
  • Obtener certificado productivo en ARCA.
  • Cargar certificado productivo en la app.
  • Validar punto de venta y tipo de comprobante.
  • Emitir una venta controlada y revisar CAE/CAEA, vencimiento, número y QR.

16. Preguntas frecuentes y resolución de problemas

Problema Causa probable Qué hacer
No veo facturación electrónica El módulo no está habilitado o la configuración fiscal general está apagada. Revisar funcionalidades del comercio y configuración fiscal del SaaS.
No puedo gestionar certificados El usuario no es administrador del comercio. Ingresar con un administrador o solicitar permisos.
Comprobante rechazado Datos fiscales, punto de venta, tipo de comprobante o datos del receptor incorrectos. Leer el mensaje, corregir datos y reintentar si corresponde.
Comprobante incierto Timeout o respuesta incompleta de la API fiscal/ARCA. Conciliar antes de reintentar para evitar duplicados.
No descarga PDF fiscal El comprobante no está autorizado o faltan datos obligatorios. Revisar estado fiscal, CAE/CAEA, número y vencimiento.
No puedo vender a cuenta corriente Falta seleccionar cliente. Asociar cliente antes de confirmar venta pendiente o parcial.
Stock incorrecto Compras no cargadas, ventas mal registradas o lote no corregido. Revisar historial, cargar compras faltantes o usar corrección de lote/stock.
No llegan notificaciones Notificaciones desactivadas, destinatarios incompletos o ventana horaria restrictiva. Revisar configuración, emails y última actividad de envíos.

Documento para uso operativo interno. La sección fiscal es orientativa y debe validarse con contador o responsable fiscal antes de operar en producción.
